# 순환 평가 문제 확인 — api-defense-lab을 독립 생성기로 재평가 (2026-11-25)

## 문제의식 (외부 리뷰에서 제기됨)

> 정답지와 평가 트래픽이 같은 출처입니다. api-defense-lab의 `traffic/`이 공격과 정상 트래픽을 만들면서 정답지도 같이 씁니다. 탐지기가 생성기의 패턴에 맞춰져 있을 가능성이 있습니다.

타당한 지적이다. api-defense-lab의 Sigma 룰과 ML 모델은 전부 `traffic/lab_traffic.py`가 만든 트래픽으로만 설계·검증됐다. 이 레포(traffic-persona-lab)는 **완전히 다른 설계**(명세 기반 상태 추출 + 페르소나 조건부 마르코프 혼합모델 + ClarkNet·NASA 교차검증된 로그정규 타이밍)로 만든 생성기라서, 이걸로 api-defense-lab을 평가하면 "탐지기가 생성기 하나에만 과적합됐나"를 직접 확인할 수 있다.

## 1차 시도 — 가짜 양성 (생성기 버그, 탐지기 문제 아님)

`generator/gen.py --send`로 20명을 api-defense-lab(DVRA)에 보냈더니 **몇 번째 사용자부터 모든 로그인이 차단**됐다. 원인: `generator/auth.py`의 회원가입·로그인 요청에 `X-Client-IP` 헤더가 빠져 있어서, 20명 전원의 로그인 시도가 전부 같은(진짜) 접속 IP 하나로 보였다 — "한 출발지가 몰아서 요청" = ML이 BOLA로 의심해 차단. 로그인이 깨지자 나머지 세션이 익명으로 보호 경로를 순회하다 `agent` 탐지 룰에도 걸렸다.

**이건 탐지기의 오탐이 아니라 생성기의 버그였다** — 고쳐서(모든 요청에 세션별 IP 태깅) 공정하게 다시 평가했다.

## 2차 시도 — 고친 뒤, 깨끗한 결과

같은 명세·같은 20명·같은 시드로, IP 태깅만 고쳐서 다시 보냈다.

```
python generator/gen.py <dvra_openapi.json> --base-url http://127.0.0.1:8089 \
    --users 20 --seed 42 --send --labels-out out/tpl_labels.jsonl --run-id tpl-eval-fixed-20261125
```

정답지(`role=normal`)를 api-defense-lab의 `labels.jsonl`에 합쳐 그 레포의 scorer로 채점했다.

| | 결과 |
|---|---|
| 독립 IP | 20개 |
| 요청 | 100건 |
| **오탐 차단** | **0건** |
| 룰 경보 받은 IP | 0개 |
| ML high 창 | 6개 (기존 레포의 알려 둔 한계와 같은 종류 — 차단 정책이 걸러 실제 차단 0) |

## 결론

**전혀 다르게 설계된 생성기로 보내도 정상 트래픽이 오탐 차단되지 않았다.** 탐지기가 `lab_traffic.py`의 패턴에만 맞춰져 있다는 우려는, 적어도 "정상 트래픽을 정상으로 본다"는 기준에서는 **이 실험으로 반증됐다.** 다만 이건 **정상 쪽만** 확인한 거다 — 공격 쪽(이 생성기로 BOLA·탐색 같은 공격을 재현해 api-defense-lab이 똑같이 잡는지)은 아직 안 봤다. `gen.py`는 아직 쓰기 요청을 실제로 안 보내서(README의 v1 한계) 그 자체로는 BOLA 열거를 재현 못 한다 — 다음 단계.

## 부수 발견
생성기의 진짜 버그(IP 헤더 누락)를 이 교차 평가 과정에서 찾았다 — 독립적인 평가가 **탐지기뿐 아니라 생성기 자신의 결함도 드러낸다**는 증거이기도 하다.
